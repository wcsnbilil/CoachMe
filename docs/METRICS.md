# 指标定义

> 本文件是给人看的说明。**代码中的唯一事实来源是**
> `CoachMeCore/Sources/CoachMeCore/Metrics/MetricCatalog.swift`。
> 两处若不一致，以代码为准，并请修正本文件。

所有角度由算法计算，与大模型无关。每个指标都绑定一个 `definitionHash`；教练参考范围
保存时会记录它当时对应的 hash，**定义一旦改变，旧范围会被拒绝复用**，而不是在新定义下
被重新解释。

数据不足时，一律显示「无法可靠计算」并给出原因，**绝不用 0、默认角度或推算值代替**。

## 坐标空间

| 空间 | 含义 |
|---|---|
| `imagePlane2D` | 归一化图像坐标（已应用视频旋转/镜像后的正立画面），x、y ∈ 0–1。此空间下的角度是**图像平面投影**，随拍摄视角变化 |
| `worldEstimate3D` | MediaPipe world landmarks：GHUM 模型输出的**米制三维估计**，原点在髋中点。它是模型对人体形态的估计，**不是标定过的动作捕捉**，其坐标轴与地面、目标线、任何世界坐标系都无关 |

**躯干坐标系**（多个指标的参考系）：原点 = 髋中点；`up` = 髋中点→肩中点；
`lateral` = 左髋→右髋（对 `up` 正交化）；`forward` = `up × lateral`。
该基底完全由被测者自身关键点构建，因此不依赖原始坐标轴约定、相机或地面假设。
注意 `up` 是**躯干长轴**，随脊柱倾斜而倾斜，**不是重力方向**。

## 第一组：单帧即可计算

### 1. 肘部内夹角 `elbowInteriorAngle`

| 项 | 内容 |
|---|---|
| 关键点 | SHOULDER, ELBOW, WRIST（按持杆侧映射为引导臂/后侧臂） |
| 公式 | 在 ELBOW 处，(SHOULDER − ELBOW) 与 (WRIST − ELBOW) 的夹角 |
| 空间 | `worldEstimate3D` |
| 参考系 | 无需外部参考，仅由三点相对位置决定 |
| 投影 | 三维向量夹角，不做平面投影 |
| 零点与方向 | 手臂完全伸直 ≈ 180°，弯曲时减小；非负，无方向性 |
| 范围 | 0–180° |
| 适用视角 | 正面 / 沿目标线 / 未知 |
| 数据不足 | 任一关键点缺失或可见度不足 → `无法可靠计算`；三点重合 → `关键点重合，角度无定义` |

**屈曲角 = 180° − 内夹角。** 两种约定在 UI 中不会混用。
此值**不代表**前臂旋前/旋后，也**不代表**手腕屈伸。

### 2. 上臂与躯干夹角 `upperArmToTorsoAngle`

| 项 | 内容 |
|---|---|
| 关键点 | SHOULDER, ELBOW, 双肩, 双髋 |
| 公式 | (ELBOW − SHOULDER) 与 (髋中点 − 肩中点) 的夹角 |
| 空间 | `worldEstimate3D` |
| 参考系 | 躯干长轴，方向为肩中点→髋中点（向下） |
| 投影 | 三维向量夹角 |
| 零点与方向 | 上臂沿躯干自然下垂 ≈ 0°，举起时增大至 ≈ 180°；无正负 |
| 范围 | 0–180° |

> **限制**：这是上臂方向与躯干长轴的夹角，**不是解剖学意义上的肩关节外展或旋转**。
> 它无法区分手臂是向前、向侧还是向后抬起——三者可能得到相同数值。

### 3. 双上臂夹角 `betweenUpperArmsAngle`

(左ELBOW − 左SHOULDER) 与 (右ELBOW − 右SHOULDER) 的三维夹角。方向一致 0°，反向 180°。
仅反映两侧上臂方向差异，不代表双臂三角形形状或手部关系。

### 4. 膝部内夹角 `kneeInteriorAngle`

在 KNEE 处，(HIP − KNEE) 与 (ANKLE − KNEE) 的夹角。伸直 ≈ 180°。
下肢常被身体或球杆遮挡，读数前请检查该帧可见度标识。

### 5. 手腕相对躯干位置 `wristPathBodyReferenced`

(WRIST − 髋中点) 在躯干坐标系 (lateral, forward, up) 上的三个分量，**除以躯干长度**
（无量纲）。因为原点与坐标轴随躯干移动旋转，**人物整体走动或镜头移动不会计入**。

App 同时提供**画面轨迹**（归一化图像坐标）。两者含义不同，UI 中分别标注：
画面轨迹包含身体整体位移，躯干坐标轨迹不包含。

## 第二组：估计值，附明确限制

以下三项**必须**满足两个前提，否则显示「尚未标记准备姿势关键帧」或「缺少三维估计数据」：

1. 模型输出了 world landmarks
2. 教练已手动标记 `准备姿势` 关键帧

### 6. 肩线转角 `shoulderLineRotation`

| 项 | 内容 |
|---|---|
| 公式 | 从准备姿势的 (右肩 − 左肩) 到当前帧 (右肩 − 左肩) 的**带符号**夹角，两者均投影到与准备姿势躯干长轴垂直的平面 |
| 参考系 | 以准备姿势那一帧的躯干长轴为旋转轴，该帧肩线为 0° |
| 投影 | 横断面（⊥ 躯干长轴） |
| 零点与方向 | 准备姿势 = 0°；绕躯干长轴按右手定则为正 |
| 范围 | −180 – 180° |

> **限制（必读）**
> - 这是**相对准备姿势**的转角，**不是相对目标线**的转角。未经标定时，球场目标线与
>   地面方向均为未知，App 不会声称知道。
> - 投影已剔除肩线沿躯干轴的倾斜分量，因此**屏幕上的肩线倾斜不会被当作轴向旋转**。
> - 即便如此，**肩线方向仍不等同于胸廓解剖学旋转**。
> - 数值来源于模型三维估计，**未经动作捕捉验证**。

### 7. 髋线转角 `hipLineRotation`

同上，使用 (右髋 − 左髋)，同一旋转轴、同一符号约定。

### 8. 肩髋分离角 `shoulderHipSeparation`

**定义为「肩线转角 − 髋线转角」**，两者均相对同一准备姿势躯干轴。肩比髋转得多时为正。

> 引用任何参考范围前，必须确认该范围也是按**这个**定义得出的。
> 不同教学体系对 X-Factor 的定义并不一致（有的相对目标线，有的相对骨盆），
> 数值不可直接互换。

## 明确不做的测量

以下内容**无法**仅凭肩、肘、腕的位置得出，App 不提供、也不估算：

- 前臂旋前 / 旋后
- 手腕屈伸、桡偏尺偏
- 球杆杆面角度
- 杆头速度、挥速

这些需要额外的识别能力（杆身/杆头检测、更高帧率、标定）和独立验证，属于后续功能。

## 关键点平滑

导入时对关键点序列应用 One Euro 滤波（`CoachMeCore/Smoothing/`），参数记录在
`AnalysisCache.smoothing` 里，随分析结果一起存盘。`AnalysisCache.frames` 始终保存
**模型原始输出**，平滑在读取时施加，因此可以随时换参数重跑而不必重新推理。

默认 `minCutoff = 5.0 Hz`、`beta = 2.0`、可见度门槛 `0.5`，在真实 24 fps 素材上扫描
确定，依据见 `docs/LIMITATIONS.md` 第六节。

三条硬约束：

1. **不修改 `visibility` / `presence`。** 那是模型自己的置信度，平滑位置不会让模型
   更确定。
2. **不补缺失的关键点。** 可见度低于门槛的样本原样透传，且不进入滤波器状态——
   陈旧位置绝不冒充观测值。
3. **不改变 `detectedPersonCount` 与任何质量判定。**
