# 产品规则

这里记录仓库所有者做过的产品决定。遇到产品问题先查这里；这里没有的，问仓库所有者，不要自己补。
新增或修改条目只能由仓库所有者确认。

## 发布形态

| 决定 | 日期 |
|---|---|
| **不商用，不上架 App Store。** 取代 2026-11-18 的「上架的第一个版本是完整版」和「上架后 AI 教练等功能正常联网」。 | 2026-11-23 |
| 用户一次只拍一个挥杆。多杆切分不再投入。 | 2026-11-18 |

## 判定与文案

| 决定 | 来源 |
|---|---|
| 外下/内下只看双手轨迹，不追踪球杆。报告只说「容易出现」某种球路，不说一定会。 | `docs/LIMITATIONS.md` |
| 外下/内下的结论写明是「手部路径」（如「外下式手部路径」），不写成或暗示杆头路径。判定标签 `nameZH` 只用于和 Python 对照，界面显示用 `displayZH`；由测试和 lint 规则 `verdict_label_in_ui` 守住。 | 仓库所有者 2026-11-23 |
| 内测版不对用户说「范围内」「没问题」「正常」。手部路径看不出杆身外下，漏判不能被当成没问题。 | PR #11 |
| 结果接近边界、追踪不稳或机位略偏时，用软说法并给拍摄建议，不给练习建议。 | PR #17 |
| 不出现任何没有对照测量支撑的准确率数字。 | `docs/LIMITATIONS.md` |
| 姿态识别、阶段识别和角度计算在本机完成；不上传完整视频。 | `README.zh-CN.md` |

## 工程上的约定

| 决定 | 日期 |
|---|---|
| 回归基准：GolfDB 400 杆的关键点数据入库。 | 2026-11-17 |
| 外下/内下的失败门槛：同一杆实时与慢动作两个版本的判定一致率；另存逐杆判定快照。 | 2026-11-17 |
| 7 阶段准确率按 GolfDB 论文口径。 | 2026-11-17 |
| 任何 PR 让基准指标下降，就算失败。 | 2026-11-17 |
| PR 上只跑快速检查；重型流程在合入 main 后或每晚跑，可手动触发。 | 2026-11-18 |
| 下一条主线是杆身/杆头跟踪（UI 迁移已完成）。 | 2026-11-23 |
| 7 个阶段一起按先后顺序选帧（有序解码）；选中的 8 帧概率几何平均低于 e^−2.0 时，当作不是一次完整挥杆，不给关键帧（门槛 −2.0 由仓库所有者选定）。 | 2026-11-24 |
| 一个视频里有两次挥杆时，暂时接受只标出其中一杆；以后另做两次挥杆的识别和提示。回归门槛 `negativeRejection` 不算这一类。 | 2026-11-24 |
| 准备帧不改用「顶点前静止帧」（`claude/address-still`、`claude/address-eval` 的实验）。在三份回归基准上重算：识别关键帧与标注关键帧判定一致 85→87/89，实时与慢动作一致率 0.9630→0.9632，用标注帧时拒判 22→23；提升在误差范围内，又要多 3 个阈值。仓库所有者同意不采用。 | 2026-11-24 |

## 还没有决定的

- 完整版和内测版以后以哪个为主，内测模式的代码要不要删。
- App 会不会通过 TestFlight 等方式给别人用。
- 仓库是否继续公开。
